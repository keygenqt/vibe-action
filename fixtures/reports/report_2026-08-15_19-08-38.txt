The contains modifier checks whether a value contains a substring and returns true or false. Use it in the form 
{tag|contains:X} where X is the substring to look for.

Basic usage: {query|contains:error} returns true if the input contains error, otherwise false.

Negation is supported with :not — {tag|contains:not:error} returns true when the substring is absent.

It is typically used inside conditional branching to drive when/then decisions:

- when: '{tag_check|contains:DIRTY}'
  then: 'echo "Dirty state found: {tag_content}"'
- when: '{tag_check|contains:not:DIRTY}'
  then: 'echo "No dirty state."'

The check works on strings, lists, and any sequence. When chained with other modifiers, place it after transformations —
for example {query|lower|contains:error} to match case-insensitively.

{tag|trim|upper|uniq|join}
{tag|split:,\s|uniq|sort|join:\n}
{tag|take:10|lower|trim}

Модификаторы можно комбинировать в любом порядке — каждый следующий применяется к результату предыдущего.

Полезные связки:
{tag|split|uniq|join} — разбить на список, убрать дубли, собрать обратно
{tag|trim|lower|contains:ошибка} — проверка наличия подстроки после нормализации
{tag|join:,\s} — склеить список через запятую с пробелом

Для проверок используйте логические модификаторы: contains, empty, equals, is_file, is_dir — они возвращают true или 
false и применяются в условиях when.

Спецсимволы внутри модификаторов: \s — пробел, \n — перевод строки, \t — табуляция.

Полный список модификаторов: https://vibe-action.keygenqt.com/docs/modifiers.html

标签系统是 Vibe Action 的核心，通过 {tag} 引用实现步骤间的数据传递和依赖编排。

基本用法：

1. 在 actions 中给每个步骤定义唯一的 tag 作为标识。
2. 在后续步骤的 action 文本中写入 {tag_name}，引擎会自动替换为该步骤的输出。
3. 执行顺序不按文件排列，而是由引擎扫描所有 {tag} 引用，构建有向无环图（DAG），用 Kahn 
算法拓扑排序，自动阻塞等待依赖解析完成。
4. 支持多依赖：一个步骤可引用多个 tag，例如 对比 {tag_a} 和 {tag_b}。
5. 循环依赖（A 需要 B、B 需要 A）会在启动时被检测并报错。

示例管道结构：

actions:
  - tag: files
    run: cmd
    action: git diff --name-only
    expect: list

  - tag: analyze
    run: small
    action: 分析以下文件变更并总结要点：{files|join:\n}

列表展开机制：

当某步骤期望 string 或执行 cmd，但引用的 tag 输出是 list 时，引擎会自动对每个元素独立执行该步骤。例如 {files} 产出 
["main.rs", "lib.rs"]，则 git diff {files} 会分别运行两次。如需阻止展开，使用 {tag|join} 将列表折叠回单个字符串。

条件分支：

action 可配置 when/then 矩阵，按顺序求值，第一个匹配的 when 触发对应 then。若全部不匹配，管道立即失败。

- tag: check
  run: cmd
  action: git status --porcelain
  expect: string

- tag: result
  run: cmd
  action:
    - when: '{check|contains:M}'
      then: 'echo 有未提交修改'
    - when: '{check|empty}'
      then: 'echo 工作区干净'

修饰符链式调用：

{tag|trim|upper|uniq|join} — 先去除首尾空白、转大写、去重，再折叠成单行。修饰符内空格用 \s 表示，例如 {tag|join:,\s} 
生成逗号加空格的序列。

在 CLI 中，{query} 标签从位置参数或系统剪贴板读取输入；在 IDE 中则由 api.input 配置决定数据来源。
